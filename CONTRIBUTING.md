# Contributing

## Scope

This repository is an architecture and research baseline. Contributions should improve evidence, clarity, traceability, safety, privacy, security, accessibility, or reproducibility. They must not add operational alerting, physical-control, surveillance, targeting, or unauthorised third-party integration capabilities.

## Contribution standard

1. Open an issue or discussion for material architecture changes before drafting them.
2. State the intended purpose, affected requirements, safety/privacy/security impact, dependencies, and verification method.
3. Use cautious maturity language. Separate facts, proposals, assumptions, and targets; link claims to primary sources or reproducible evidence.
4. Update the relevant ADR, risk entry, traceability row, and references with the design change.
5. Do not add secrets, personal data, proprietary datasets, or material you cannot license for this repository.
6. Keep examples synthetic and mark them as such.

## Review expectations

Changes to warning workflows, sensors, AI, data flows, identity, cryptography, external providers, or physical operations require review for safety, security, privacy, dual-use, accessibility, and jurisdictional impact. The maintainer may decline a contribution that exceeds the research boundary.

## Documentation conventions

Use descriptive headings, relative links, plain language, and stable requirement identifiers. Define acronyms on first use. Do not claim a standard conformance, performance result, or regulatory status without an evidence record conforming to [PROJECT_STATUS.md](PROJECT_STATUS.md).
